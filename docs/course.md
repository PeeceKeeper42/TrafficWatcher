# План курса

Проект и его вехи — в [`readme.md`](readme.md) §1 (**M1** паритет → **M2** фичи → **M3** RMS-песочница с
имитационным моделированием). Виды тестов и контур качества — в [уроке 8](lessons/08-testing-strategy.md).
Инфраструктура (VDS, воркеры, n8n, доска) — в [уроке 15](lessons/15-infrastructure.md).
Решения — в [`adr/`](adr/readme.md).

Цель курса: провести приложение через все три вехи на **Qt 6.10.2 / QML / C++20 / современном CMake
(CTest, CPack, CDash)**, на Windows + Linux + macOS, с платформозависимым кодом в выделенном слое
и с тестовым контуром уровня коммерческого продукта.

## Принципы

1. **Код пишу сам.** Ассистент: теория → направление → ревью → доработки; пишет тексты в `docs/lessons/`
   и `docs/readme.md`, создаёт `docs/answers/` с вопросами, а в моих ответах ему разрешено только дописывать
   оценку под ответом (`AGENTS.md` §1.1). Обязательства ассистента целиком — в [`../AGENTS.md`](../AGENTS.md).
2. **Модуль закрывается работающим артефактом**, а не «разобрались».
3. **Тесты — сквозной поток**, а не отдельный модуль в конце: у каждого модуля есть строка «Тест-приёмка»
   (виды тестов — по таксономии [урока 8](lessons/08-testing-strategy.md) §2).
4. **Решение без ADR не принято**: у модуля есть колонка ADR.
5. **Инфраструктура — отложена до конца** (урок 15): до этого только локальные пресеты, иначе автоматизируем хаос.
6. **Вопросы для закрепления живут только в `docs/answers/NN-*.md`** — ассистент создаёт этот файл вместе с
   уроком, ответы вписываю я. В теле урока вопросов нет.

# Блок I. Фундамент (модули 0–2)

## Модуль 0 — Территория и инструмент

Слит в урок 1.1 ([`lessons/01-cmake-target-model.md`](lessons/01-cmake-target-model.md) §0 и §6):
что изменилось в Qt6 (QML-модули, регистрация типов, versionless targets), что сломалось на CMake 4,
какой тулчейн тянет C++20, а какой нет.

**Артефакт:** Qt 6.10.2 + MSVC 2022/GCC 13+ + Ninja; ADR-0001.

## Модуль 1 — Современный CMake как граф таргетов

| Урок | Тема |
|---|---|
| 1.1 | Фазы CMake, target-модель, `PRIVATE/PUBLIC/INTERFACE`, imported/alias, пресеты, multi-config, генераторные выражения |
| 1.2 | Matrix-presets (`OS × compiler × config`), `toolchainFile`, `CMakeUserPresets.json`, один пресет для CLion/Qt Creator/CI |
| 1.3 | Layout: `app/ core/ ui/ platform/ tests/ packaging/`; публичные заголовки в `include/<ns>/`; `target_compile_features(cxx_std_20)`; почему нет `file(GLOB)`; `cmake/Tw*` функции vs macro |

**Артефакт:** два пресета собирают с нуля, `--graphviz` показывает ожидаемый граф.
**Тест-приёмка:** «чистая сборка» как CI-джоб (rm -rf build → configure → build) + `cmake --graphviz` дифф.
**ADR:** 0001, 0002, 0003, 0004.

| Урок | Тема |

## Чек-лист «курс пройден»

- [ ] Ни одного `include_directories` / `link_directories` / `add_definitions` верхнего уровня.
- [ ] Ни одного хардкода пути к Qt вне пресетов.
- [ ] Ни одного `qmlRegisterType`, ручного `qmldir`, `.qrc` для QML.
- [ ] `#ifdef` по ОС — только в `src/platform/`.
- [ ] Тесты ядра не линкуют QtQuick; ядро запускается headless.
- [ ] В ядре нет обращений к реальному времени и глобального singleton-таймера (ADR-0007).
- [ ] Есть CI-матрица из 3 ОС, страница CDash с историей, self-hosted runner и n8n-оповещения.
- [ ] Каждый вид теста из [урока 8](lessons/08-testing-strategy.md) §2 либо применяется, либо имеет явный отказ с причиной.
- [ ] `cpack` даёт устанавливаемый пакет для каждой целевой платформы, и он прошёл smoke.
- [ ] M1/M2/M3 имеют задокументированные критерии готовности ([`readme.md`](readme.md) §1).
- [ ] На каждый пройденный урок есть заполненный `answers/NN-*.md`.
- [ ] Все нетривиальные решения оформлены как ADR, очередь из `adr/readme.md` закрыта.
