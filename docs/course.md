# План курса

Проект и его вехи — в [`readme.md`](readme.md) §1 (**M1** паритет → **M2** фичи, тема и стиль UI →
**M3** карта дорог со светофорами, 2D-визуализатор и развод на клиент-сервер → **M4** рост моделей и
функционала → **M5** режим 3D при той же модели, где 2D — вырожденный случай 3D). Виды тестов —
предварительная карта в уроке 1.5 и полная таксономия в уроке 8.1 (оба не написаны).
Инфраструктура (VDS, воркеры, n8n, доска) — в уроке модуля 19 (не написан).
Решения — в [`adr/`](adr/readme.md).

Цель курса: провести приложение через все пять вех на **Qt 6.10.2 / QML / C++20 / современном CMake
(CTest, CPack, CDash)**, на Windows + Linux + macOS, с платформозависимым кодом в выделенном слое
и с тестовым контуром уровня коммерческого продукта.

## Принципы

1. **Код пишу сам.** Ассистент: теория → направление → ревью → доработки; пишет тексты уроков
   (`docs/lessons/`) и методики (`docs/methodology.md`), создаёт `docs/answers/` с вопросами, а в моих
   ответах ему разрешено только дописывать оценку под ответом (`AGENTS.md` §1.1). Обязательства ассистента
   целиком — в [`../AGENTS.md`](../AGENTS.md).
2. **Модуль закрывается работающим артефактом**, а не «разобрались».
3. **Тесты — сквозной поток**, а не отдельный модуль в конце: у каждого модуля есть строка «Тест-приёмка»
   (виды тестов — по карте из урока 1.5, полная таксономия — урок 8.1).
4. **Решение без ADR не принято**: у модуля есть колонка ADR. Открытое решение остаётся открытым: план не
   делает вид, что выбор сделан, — в очереди ADR такие помечены словами «не принято», а урок обязан кончаться
   цифрой, по которой решение примется (пример — ADR-0030 про способ растеризации).
5. **Инфраструктура — отложена до конца** (урок 19): до этого только локальные пресеты, иначе автоматизируем хаос.
6. **Вопросы для закрепления живут только в `docs/answers/NN-*.md`** — ассистент создаёт этот файл вместе с
   уроком, ответы вписываю я. В теле урока вопросов нет.
7. **Времени в плане нет.** Ни один урок и модуль не оценивается в часах: часы появляются только как
   факт закрытого модуля (таблица статуса, [`methodology.md`](methodology.md) §6). Оценка «сколько
   это займёт» делается до того, как известно, чего я не знаю, и потому всегда оптимистична.
8. **У курса есть внешний след:** закрытый модуль — тег с заметкой, закрытый блок — устная защита по трём
   вопросам (раздел «Курсовые ритуалы»).

## Карта зависимостей тем

Порядок модулей линейный, темы — нет: «ни одного `#ifdef` вне `platform/`» опирается на генераторные
выражения, «тест ядра не линкует QtQuick» — на ownership `QObject`, «100 перекрёстков быстрее realtime» —
на событийный цикл. Таблица нужна, чтобы при перестановке модулей было видно, что рвётся, а по строке
«вроде проходили» — где именно проходили.

Для M3–M5 таблица важнее, чем для ранних блоков: карта, протокол состояния и 3D-представление стоят на
одних и тех же данных. Рвётся строка «карта как данные» — рвутся и визуализатор, и клиент-сервер, и переход
в 3D.

# Блок I. Фундамент (модули 0–2)

## Модуль 0 — Территория и инструмент

Слит в урок 1.1 (не написан; тема инвентаря машины и блокеров — его блоки 3 и 8):
что изменилось в Qt6 (QML-модули, регистрация типов, versionless targets), что сломалось на CMake 4,
какой тулчейн тянет C++20, а какой нет.

**Артефакт:** Qt 6.10.2 + MSVC 2022/GCC 13+ + Ninja; ADR-0001.

## Модуль 1 — Современный CMake как граф таргетов

| Урок | Тема |
|---|---|

| 1.5 | Предварительная карта видов теста: unit / component / integration / contract / UI / golden — что ловит каждый и чего от него ждать нельзя; используется в строках «Тест-приёмка» всех последующих модулей, полная таксономия — 8.1 |

`git log --oneline` по последним коммитам: в каждом одна причина, нет коммита, где правка формата идёт
вместе со сменой поведения.
**ADR:** 0001, 0002, 0003, 0004, 0020.

# Блок VII. Карта и клиент-сервер (модули 15–16) — M3

Приложение перестаёт быть светофором: появляется карта дорог, по ней едут машины, а показ состояния

разрезанная без представления, проверяется на пустоте.

**Артефакт:** карта с двумя типами дорог и двумя классами машин; статистики выгружаются файлом; скрипт задаёт
«авария на полосе в 08:12» без пересборки; два прогона сравниваются в интерфейсе.
**Тест-приёмка:** property-based на моделях дорог, `long`-нагрузка с порогом (ADR-0019), golden трасс, TSan на
воркерах, fuzz парсера скриптов.
**ADR:** 0017, 0018, 0019.

## Модуль 18 — M5: режим 3D при той же модели мира

| Урок | Тема |
|---|---|
| 18.1 | Граница представления: что 3D-слой имеет право знать о модели мира и чего не имеет права в ней менять; contract-тест из 15.5 усиливается до «ядро не знает про 3D»; здесь же проверяется обещание 15.1: `z` перестаёт быть нулём только в представлении, валидация модели при этом не правится (ADR-0028) |
| 18.2 | Средства 3D в Qt 6.10: Qt Quick 3D (`View3D`) vs Qt 3D Render vs свой слой на `QRhi`/Vulkan — сравнение из 15.4 переносится в 3D, а не начинается заново; доступность модулей в моей сборке и на трёх ОС (проверить установщик/`qt_config`), цена каждого выбора; материалы и палитра берутся из токенов 14.2 (ADR-0028, ADR-0030) |
| 18.3 | Режим, а не второе приложение: одна сцена представления и две проекции (ортография ↔ перспектива), переключение 2D ↔ 3D посреди прогона без остановки симуляции и без потери камеры; instancing и отсечение невидимого для тысяч машин, LOD, свет; golden-тесты фиксированных ракурсов в обоих режимах и пустой diff трасс при переключении; тот же сервер из 16 |

**Артефакт:** та же карта M4 показывается в 3D тем же клиентом, переведённым в другой режим; 2D остаётся
основным представлением в CI и в повседневной работе; в `core` за веху нет ни одного коммита, меняющего
поведение.
**Тест-приёмка:** contract «модель не знает про 3D»; diff трасс одного клиента в режимах 2D и 3D пуст;
бюджет кадра в 3D с порогом и профилировочный отчёт.
**ADR:** 0019, 0028, 0030.

# Блок IX. Инфраструктура (модуль 19)

Материал и последовательность — в уроке модуля 19 (I0…I6): VDS, образы контейнеров тулчейна (реализация

ночные лоты.

Граница с модулем 12 — одна линия, а не два места: 12.1 фиксирует, **из чего** собирается окружение,
12.2–12.3 — **что** выполняется в контуре (CDash + hosted CI на трёх ОС), 19 — **где** это выполняется
без моего ноутбука (свой сервер, свой runner, своё хранилище). Всё, что модуль 19 автоматизирует, уже
существует как команда или пресет, которые я выполнял руками; автоматизировать то, чего нет, нельзя. К
модулю 19 это касается и пары процессов из 16: CI поднимает сервер и клиент так же, как я поднимал их
руками, и прогон в 3D-режиме там же, где в 2D. Схема ветвления и релиза принята раньше — в 1.4 (ADR-0020),
здесь она только исполняется по тегу.

**ADR:** 0011 (CI-движок), 0012 (macOS), 0013 (доска).

## План Б: что режем, если модуль встал

Модуль не имеет права стоять молча. Триггер — не «долго» и не «скучно», а **незакрытый пункт DoD после
двух отдельных попыток с разными гипотезами**: тогда упрощение выбирается явно, фиксируется ADR со
статусом `Заменено` и строкой ниже. Упрощение без записи — это дыра в знаниях, а не план.

| Модуль | Если встал | Упрощение | Чем плачусь |
|---|---|---|---|
| 5 | `QRangeModel` не даёт нужного поведения редактирования | ручная `QAbstractListModel`, `QRangeModel` — отдельным уроком-догоняйкой | знакомство с новинкой 6.10 отложено; модель и контракты остаются |
| 7 | Wayland-специфика хоткеев и tray не разбирается до состояния «понятно, почему» | `X11`-ветка + явный отказ от Wayland с причиной в ADR-0008 | «три ОС» превращаются в «Windows / Linux-X11 / macOS» |
| 7 | Дампы не собираются на одной из ОС | Breakpad/qBreakpad только там, где работает; вторая ОС — лог + код возврата, отказ задокументирован | постмортем по этой ОС делается пересбором с флагами отладки |
| 9 | golden-скриншоты разъезжаются между GPU/драйверами | golden только для offscreen/headless-слоя, визуальное — проверкой свойств и ручным смотром | часть пиксельных регрессий уходит из автоматического контура |
| 10 | fuzz или property-based не запускаются под MSVC | fuzz-контур только на Linux-пресете, порог в CI на нём же | деградация Windows-парсера ловится позже |
| 12 | hosted-раннер не даёт нужный тулчейн | macOS — ночной лот через cloud (ADR-0012), обязательная матрица — win/linux | macOS перестаёт блокировать мерж, остаётся nightly |
| 13 | Миграции конфигурации не сходятся с форматом M1 | формат замораживается версией, миграция — одна (последняя → текущая), остальные в очереди | старые файлы открываются только через ручную конвертацию |
| 14 | Собственный стиль Control не доводится до состояния «можно поддерживать»: правки множатся, golden-снимки разъезжаются | готовый стиль + токены темы; собственный стиль остаётся на двух контролах как образец, остальное — через `background`/`contentItem` | от ADR-0029 остаётся токеновая часть; свой стиль помечается отказом с причиной, а не забывается |
| 15 | Отрисовка карты с тысячами машин не влезает в бюджет кадра | отсечение по видимой области, упрощённый стиль дорог, меньше перекрёстков на экране | «простенький визуализатор» остаётся визуально простым, сложность переносится в камеру |
| 15 | Из четырёх слоёв растеризации ни один не даёт нужный бюджет, а сравнение тонет в объёме | сравниваются только два: штатный scene graph и свой узел поверх него; «голый» Vulkan переносится в ADR-0030 со статусом «отложено» и критерием возврата | часть знания о `QRhi`/Vulkan остаётся незакрытой; выбор средства в M5 делается на этих же двух слоях |
| 15 | Продольная динамика «еду-стою» не даёт устойчивой очереди на стоп-линии | одна полоса и одна очередь на ребро, без обгонов и перестроений | M3 показывает трафик, но не манёвры; перестроения уезжают в 17.2 |
| 16 | Два процесса не сходятся по частоте обновления или ловят гонку при снимке состояния | сервер остаётся единственным владельцем состояния, клиент шлёт только команды, обновление — один полный снимок на кадр | интерактивность редактора ниже; детерминизм и воспроизводимость сохранены |
| 17 | Клеточная модель не даёт статистик по отдельным машинам, агентная не масштабируется | клеточная — для «сотни перекрёстков», агентная — для сцен до 25 перекрёстков; оба прогона описаны пресетами | M4 не закрывает масштаб и поведение одним прогоном |
| 18 | Выбранное средство 3D недоступно или не тянет сцену на части ОС | 3D только там, где тянет; 2D остаётся основным представлением и контуром CI | M5 закрыта частично: на недоступной ОС режима 3D нет, отчёт об этом — часть приёмки |
| 18 | Переключение 2D ↔ 3D на лету не сходится: код плоской сцены размазан по слою представления | 3D становится вторым представлением, переключение — перезапуском окна с той же трассой | тезис «2D — вырожденный случай 3D» оформляется отказом в ADR-0028: два golden-контура вместо одного, diff между клиентами вместо diff режимов |

## Чек-лист «курс пройден»

- [ ] Ни одного `include_directories` / `link_directories` / `add_definitions` верхнего уровня.
- [ ] Ни одного хардкода пути к Qt вне пресетов.
- [ ] Ни одного `qmlRegisterType`, ручного `qmldir`, `.qrc` для QML.
- [ ] `#ifdef` по ОС — только в `platform/` (layout из 1.3).
- [ ] Тесты ядра не линкуют QtQuick; ядро запускается headless.
- [ ] В ядре нет обращений к реальному времени и глобального singleton-таймера (ADR-0007).
- [ ] Есть CI-матрица из 3 ОС, страница CDash с историей, self-hosted runner и n8n-оповещения.
- [ ] Каждый вид теста из таксономии модуля 8 либо применяется, либо имеет явный отказ с причиной.
- [ ] `cpack` даёт устанавливаемый пакет для каждой целевой платформы, и он прошёл smoke.
- [ ] Симуляция карты живёт в отдельном процессе: клиента можно убить посреди прогона, трасса при этом
      совпадает с headless-прогоном (ADR-0027).
- [ ] Тема — данные: ни один экран не задаёт цвет, отступ или тайминг литералом, каждый режим темы имеет
      golden-снимок (ADR-0029).
- [ ] Способ растеризации выбран сравнением, а не привычкой: таблица «scene graph vs свой узел vs `QRhi` vs
      Vulkan» с цифрами лежит в уроке 15.4 и оформлена ADR-0030 (или зафиксированным отложением).
- [ ] Одна и та же сцена показывается в 2D и в 3D переключением режима посреди прогона, diff трасс пуст,
      а `core` после M5 не отличается по поведению от `core` после M4.
- [ ] M1–M5 имеют задокументированные критерии готовности ([`readme.md`](readme.md) §1).
- [ ] На каждый пройденный урок есть заполненный `answers/NN-*.md`.
- [ ] Каждый блок I–IX закрыт устной защитой по трём вопросам, вердикт записан.
- [ ] На каждый закрытый модуль есть тег `m<NN>-done` с заметкой, а в таблице статуса — фактические часы.
- [ ] По каждой строке «Плана Б» решение принято и оформлено: либо упрощение с ADR `Заменено`, либо оно не
      потребовалось.
- [ ] Все нетривиальные решения оформлены как ADR, очередь из `adr/readme.md` закрыта.
